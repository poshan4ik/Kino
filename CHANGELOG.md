# Changelog

## [Unreleased] — покупка в один шаг + Kaspi/Халык по всему пути клиента

- **Клиентский флоу теперь «выбор мест → сразу оплата»**: кнопка на странице выбора мест — «Оплатить · сумма» (была «Забронировать»), подсказка перечисляет способы; после отправки клиент попадает на страницу оплаты с таймером удержания и Kaspi Gold / Халык Банк / картой.
- Кнопки сеансов на афише/фильме открывают модалку, где способы оплаты по умолчанию **Kaspi Gold, Халык Банк, карта** (было только «Карта»), с бренд-метками и пояснением про демо-шлюз; после выбора Kaspi/Халык модалка перенаправляет в шлюз.
- `POST /api/bookings/pay/` understands `kaspi`/`halyk`: создаёт PaymentIntent на каждую бронь и возвращает `redirect` в демо-шлюз (до этого клиентский метод kaspi был запрещён, а оплачивался только мгновенно); схема OpenAPI приведена к `Payment.METHOD_CHOICES`.
- Вход: скрытое поле `next` в форме логина — после авторизации клиент возвращается на страницу, с которой начинал (не теряется путь к оплате).
- Метки/UI: «Бронь подтверждена» → «Оплата прошла», «Время брони» → «Место держится», сообщение после выбора мест — «Завершите оплату: Kaspi Gold, Халык или карта».
- Новые API-тесты: kaspi/halyk через `/api/bookings/pay/` (redirect + intent на каждую бронь), запрет `cash` для клиента сохранён. Итог: **167 тестов, OK**.
- Проверено вживую (runserver): регистрация → сеанс → места → оплата Kaspi → демо-шлюз → билет с QR → профиль.

- **Холд мест синхронизирован с ТЗ отчёта — 14 минут**: дефолт `BOOKING_HOLD_MINUTES=14`, сигнал `booking_pre_save` больше не хардкодит 15 минут (единый источник — настройки), тексты в UI берутся из настроек.

- Шаблон кассы: отмена брони со staff-страницы идёт через бизнес-эндпоинт `POST /api/bookings/{id}/cancel/` вместо сырого DELETE.

- Лимит одновременной оплаты приведён к единому источнику `settings.BOOKING_MAX_SEATS` (был хардкод «6» в сериализаторе и view).

- CSV-экспорт продаж: перепутанные местами `date_from`/`date_to` автоматически упорядочиваются (как в отчёте менеджера).
- Обновлены `docs/MODELS.md` (TicketType, PaymentIntent), `docs/API.md` (платёжный шлюз/webhook, POST /api/payments/), README (таймер 14 мин, тесты).

- Итог: **164 теста, OK**; покрытие `cinema/` — **90%** (цель ≥75%).

### Этап 1 — Репозиторий
- `requirements.txt` с полными пинами, расширенный `.env.example`, `LICENSE` (MIT), честный `README.md`, `.gitignore`.

### Этап 2 — Settings и безопасность
- Все секреты/хосты/БД через env (`DJANGO_SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`, `DATABASE_URL`), `dj-database-url`, WhiteNoise, security-блок при DEBUG=False (SSL, secure-cookies, HSTS), DRF: пагинация, троттлинги, `IsAuthenticated` по умолчанию, Swagger (`/api/docs/`), логирование, бизнес-лимиты в settings.

- `TIME_ZONE=Asia/Almaty`, `timezone.localdate()` вместо `date.today()`.

### Этап 3 — Логика и баги
- Новый `cinema/services.py`: атомарный холд («всё или ничего», `select_for_update`), отмена, возврат (нельзя после начала сеанса), единые проверки (прошедший сеанс, лимит мест, принадлежность залу).
- `role`/`is_active` read-only для пользователя; `UserAdminSerializer` для staff-CRUD.
- Дашборд: 7-дневный график 2 агрегатами вместо 14 запросов; `/api/movies/` без N+1 (prefetch сеансов).
- `IsCashierRole`: confirm_payment/cancel/refund/expire_old — без контролёра.
- `Session.clean`: буфер `SESSION_BUFFER_MINUTES` из настроек.

### Этап 4 — Недостающие функции

- Команды `seed_demo` (идемпотентный демо-набор с выводом паролей) и `ensure_admin` (суперпользователь из env, без пароля в коде).
